NFA1 notes — the entropy engine

Right — it's a range coder (the LZMA-style carryless binary arithmetic coder), and the "uint32" is specifically the interval width.

The exact state (acpcm.cpp:175–221):

fieldtyperole
rangeuint32_t interval width; starts 0xFFFFFFFF, stays in [2^24, 2^32)
lowuint64_t interval base; 64-bit only so a carry can push into bit 32
cache, cache_sizeuint8_t, int64_t delay/buffer emitted bytes until the carry is resolved
code (decode)uint32_t the offset within the current interval

So "uint32 arithmetic coding" is accurate for the interval (range/code), but the encoder's accumulator is 64-bit. It's not big-integer arithmetic coding — everything is 32-bit-ish and byte-renormalized.

How the pieces fit:

  • Probabilities are 11-bit: total 2048, RC_PROB_INIT = 1024. bound = (range >> 11) * p — one multiply and a shift, which is why it's "uint32-friendly."
  • Renormalization is base-256: RC_TOP = 1 << 24. Whenever range drops below it, one byte is shifted out and range <<= 8. That leaves 8 bits of headroom so the next range >> 11 product can't overflow a uint32.
  • Carry handling: low is uint64_t and rc_shift_low inspects bit 32 ((uint32_t)(low >> 32)) to carry into buffered bytes — the classic scheme that avoids the expensive "renormalize with carry propagation" of textbook arithmetic coding. cache_size is how many 0xFF bytes are pending.
  • Flush is a fixed 5 shift-lows (rc_flush), which is why the 10-decision example produced 6 bytes — 1 real + 5 tail.
  • Two symbol flavors on the same coder:
    • binary (EncCtx::bit / DecCtx::bit) with an adaptive 11-bit uint16_t probability;
    • multi-symbol (rc_enc_multi / DecCtx::multi / multi_tree) with a cumulative-frequency table, P(sym) = (cnt[sym]+1)/(tot+M), using 64-bit products to avoid overflow. NFA4 stays byte-identical because multi_tree computes the same floor products via the Fenwick tree.
  • fixed(v, n) codes n raw bits with a uint16_t p that starts at 1024 within that call — so for n = 1 it's exactly one equiprobable bit (the mantissa case), while header fields (16/32-bit) get a mild adaptive model over their own bits.

So: a 32-bit, byte-renormalizing, carry-cached range coder with 11-bit adaptive binary models and an optional cumulative multi-symbol interface. That's the whole entropy engine; NFA1–NFA4 differ only in the models/symbols fed into it.
